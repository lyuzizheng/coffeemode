## 2. Efficiency — no duplication via helpers (S1)

S1 extracted the pre-S1 duplication (`db.integration.test.ts` + `images.integration.test.ts` shared `provisionTestDatabase`/`runMigrations`/R2 helpers inline) into `web/tests/helpers/*` and `web/tests/setup.ts`.

- One writer per production change still holds (`AGENTS.md`). Feature code composes shared helpers, never embeds or duplicates them (DG91).
- Product parameters remain in `web/config/*.yaml` and are consumed live through production readers (DG107); `runtime-config.integration.test.ts` + `staging-journey.test.ts` + the T24 row pin the values in effect, not a schema snapshot.
- `vitest.config.mts` `include` collects only `tests/**/*.test.*`, so `web/tests/helpers/**` contributes no test files (helpers are reached by direct `../helpers/*` subpath imports); `web/tests/setup.ts` resets the in-memory rate limiter and cleans up React trees once.
- `npm run test:unit` (components, jsdom) needs no Docker; `RUN_INTEGRATION=1` suites are `describe.skip` by default so a run without the flag collects nothing live.
